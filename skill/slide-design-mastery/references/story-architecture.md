# Story architecture: argue, don't merely decorate

## Prewriting form
1. Audience: what do they already know, believe, and want?
2. Decision: what should they understand, decide, approve, or remember?
3. Compression: write the whole talk in one declarative sentence.
4. Proof: list 3–5 pieces of evidence or demonstrations necessary for that sentence.
5. Friction: identify what may confuse or challenge listeners.
6. Throughline: order slides to reduce uncertainty in steps, not follow the outline of a source report automatically.

## Story arcs
**Executive decision:** answer first → evidence → risks → alternatives → decision/ask.
**Investor pitch:** problem → consequence → solution → proof → why-now → business model → go-to-market → differentiation → team → ask. Do not invent traction.
**Academic defense:** question → research gap → hypothesis → dataset/protocol → method → metrics → results → ablations/error analysis → limitations → contribution.
**Instruction:** prior knowledge → learning objective → concrete example → mechanism → guided practice → edge case → retrieval test.
**Narrative keynote:** tension → character/user → discovery → turning point → insight → call to action.
**Data briefing:** decision question → definition/timeframe → key chart → decomposition → alternatives/uncertainty → action.

## Headline discipline
- Use an assertion where evidence exists: "The revised model cuts errors on rare graphemes" (only if established).
- If evidence isn't there, frame a question: "Can a smaller encoder retain grapheme detail?"
- Keep one headline claim and one main proof object per slide.
- Eliminate vacuous labels such as "The Challenge" unless section orientation requires them.
- Copy should sound spoken by a knowledgeable presenter, not marketing automation. Remove "revolutionize", "leveraging", "cutting-edge" unless genuinely accurate.

## Slide map template
`# | job | audience question | assertion headline | main evidence | image/plot/diagram | speaker-only note | citation | status`
Use this table *before* producing layouts.

## Pacing
- Alternate cognitive workload: orient → show evidence → interpret → transition.
- Add breathing space after complex systems diagrams; an insight slide with one important conclusion can be valuable.
- Merge adjacent slides when same chart/data repeats; split when two independent claims compete.
- For 10-minute talk, 8–12 purposeful slides is a starting heuristic, not a law.
