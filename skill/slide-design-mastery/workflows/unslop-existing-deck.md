# Workflow: repair an AI-looking deck without breaking it

1. Preserve a copy and document original slide count, headlines, intended audience and measurable claims.
2. Score structural issues using `references/anti-slop-audit.md`. Identify 3 biggest system-level problems and which slides demonstrate them.
3. Verify content before altering graphs/diagrams; enumerate invariant facts and constraints.
4. Inspect a supplied template’s master, layouts, placeholders, and theme before choosing a visual direction; preserve required branding.
5. Run the ten-tell checklist and independently authored repair prompt in `references/anti-slop-audit.md`; retain justified exceptions. Perform whole-deck passes: **narrative**, **layout/spacing**, **copy**, **type**, **data/images**, **detail**, **motion**, **QA**.
6. Use intentional variety: switch from generic icon card to real workflow, plot, screenshot, evidence comparison, quote, or one-sentence assertion when semantic function warrants.
7. Preserve slide order and claims unless user authorized restructuring. On changes, report old → new for each significant slide.
8. Build and render deck; compare original/after contact sheets. Repair clipping and readability defects.
9. Report source checks, intentional visual choices and which parts remain non-editable/unverified.

**Regression check:** a cleaner slide that erases an important limitation or changes a numeric comparison is not an improvement.
