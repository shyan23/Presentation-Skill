# Example: academic computer vision defense (illustrative, no claimed data)

**Audience:** faculty evaluating technical novelty, reproducibility and limits. **Style:** `academic-precision`. **Functionality:** native editable diagrams, properly readable math, appendix slides and citation ledger.

| # | Function | Claim/headline draft | Proof object |
|---:|---|---|---|
| 1 | Orientation | "Can writer-disjoint evaluation change our conclusion?" | precise question, representative data |
| 2 | Context | "Line detection must preserve thin strokes and disjoint regions" | verified annotation example |
| 3 | Gap | "Existing detectors struggle when lines intersect" | observed errors if provided; otherwise hypothesis |
| 4 | Method | "The pipeline separates geometry, style and synthesis" | system diagram distinguishing data and model |
| 5 | Evidence | "Leakage checks determine whether evaluation is credible" | clean split diagram with actual numbers once supplied |
| 6 | Mechanism | "Reference style conditions the generator at inference" | input/style-conditioning schematic |
| 7 | Design trade-off | "Five style exemplars trade robustness for compute" | structured comparison; claims labeled hypothesis |
| 8 | Result | "[Verified metric headline pending]" | chart placeholder tied to experiment table |
| 9 | Error analysis | "[Observed failure category pending]" | genuine difficult examples |
| 10 | Ablation | "[Verified ablation finding pending]" | baseline/variant data table |
| 11 | Limits | "What we cannot conclude yet" | sampling caveats, train/test boundaries |
| 12 | Action | "Next experiment: split-clean writer evaluation" | reproducible plan and owner |

**Design note:** no fake F1 values; diagrams visually distinguish training from inference and shown inputs from learned parameters. Text should remain editable.
